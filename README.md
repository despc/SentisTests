# SentisTests

Плагин Torch для Space Engineers — стенд для проверки и замеров остальных плагинов (SentisOptimisations,
SentisGameplayImprovements, SentisAdventures, VirtualGarage) на живом сервере. Сценарий спавнит в мир то,
что нужно проверить, подключает при необходимости фейковых клиентов, гоняет игру, замеряет кадры,
выделения памяти, репликацию и проверяет результат. Всё созданное тестом удаляется после прогона.

Подробные отчёты по замерам производительности лежат в `docs/*.md` (на английском).

## Установка и настройки

Пример файла со всеми параметрами и комментарием к каждому: [`SentisTests.cfg.example`](SentisTests.cfg.example).

- Плагин кладётся в `Plugins\SentisTests`.
- `EventTimerLogs` (по умолчанию `false`, галочка на странице плагина): деревья вызовов медленных событий игры в логе.
  Выключено при старте — патчи EventTimer не ставятся вовсе; включение на ходу ставит их сразу.
- Настройки хранятся в `Instance\SentisTests.cfg`.
- Ставить только на тестовый сервер: сценарии меняют мир.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `AutoRun` | `false` | Запустить сценарии сами после загрузки мира. |
| `AutoScenarios` | пусто | Какие сценарии запускать при `AutoRun` (пусто — все). |
| `AutoRunDelaySeconds` | `20` | Пауза после загрузки мира перед автозапуском. |
| `DefaultTimeoutSeconds` | `300` | Таймаут сценария, если сценарий не задал свой. |
| `CleanupAfterTests` | `true` | Удалять тестовые сущности после прогона. |
| `CleanupDelaySeconds` | `60` | Сколько тестовые сущности остаются в мире после сценария, чтобы их осмотреть; `0` — удалить сразу. При автоматическом прогоне удаляются сразу. |
| `ReportDirectory` | `SentisTests` | Куда писать отчёты (в `Instance`). |
| `EnableDebugBridge` | `false` | Включить локальный HTTP/MCP-мост. |
| `DebugBridgeToken` | пусто | Токен моста. Хранится только в конфиге стенда, никуда не публикуется. |
| `OwnerPlayerName` | пусто | Игрок-оператор, у которого сценарии ищут персонажа. |

## Команды

| Команда | Что делает |
|---|---|
| `!test list` | Список сценариев. |
| `!test run <имя> [имя…]` / `!test run all` | Запустить один, несколько или все сценарии по очереди. |
| `!test stop` | Прервать текущий сценарий и очистить очередь. |
| `!test cleanup` | Удалить все тестовые сущности, оставшиеся в мире. |
| `!test status` | Текущий сценарий и последние результаты. |
| `!test results` | Все результаты этой сессии. |

Результат каждого сценария — строка `[TEST] PASSED|FAILED <имя> (время) - итог` в логе Torch. Отчёты
пишутся в `ReportDirectory`.

## DebugBridge

Локальный мост для осмотра мира и управления гридами из скриптов и агентов. Слушает только `127.0.0.1`,
каждый запрос требует токен (`DebugBridgeToken`, не короче 32 символов, иначе мост не запускается). Всё, что трогает мир, выполняется на игровом потоке.

REST:
- `GET /grids`, `/grid?id=`, `/at?x=&y=&z=&r=` — гриды и что вокруг точки;
- `POST /move`, `/orient`, `/vel`, `/delete`, `/park`, `/unpark` — двигать, поворачивать, задавать
  скорость, удалять, держать грид в точке;
- `POST /test {name}` — поставить сценарий в очередь;
- `GET /status`, `GET /log?n=` — состояние и хвост лога;
- MCP (JSON-RPC поверх SSE) на `/mcp/sse` и `/mcp/message` — те же возможности как инструменты.

## Инфраструктура

- **`TestScenario` / `TestRunner`.** Сценарий — корутина по кадрам: шаги, ожидания условий с таймаутом,
  проверки (`Check`), заметки в лог (`Note`). Раннер ставит сценарии в очередь, ловит исключения,
  вызывает `Cleanup()` и удаляет всё, что сценарий пометил (`Track`), и всё с префиксом `ST-47351-`.
- **`WorldApi`.** Спавн гридов из object builder, чертежей, встроенных ресурсов и авторских гридов мира
  оператора; поиск блоков; снятие паузы мира.
- **`FakeClients`.** Внутрипроцессные фейковые клиенты с игроком и персонажем, эмуляцией сети (RTT,
  потери) и движением. Сервер реплицирует им мир как настоящим, а тест видит, что каждому клиенту
  отправлено: `ArrivedCount`, `Arrivals`.
- **`TickMetrics`, `FrameProbe`, `AllocProbe`.** Время кадра симуляции (среднее, p95/p99/p99.9, максимум,
  число кадров > 16.7/33.3 мс), время отдельных методов, выделения памяти.
- **`SafeZoneProbe`.** Хуки безопасных зон на время сценария: проверки форм, события фантома, обновление
  зоны, блокировки моторов, стоимость отслеживания гридов SentisOptimisations, что зона разослала клиентам.
- **`LeaveTargets`.** Разбор IL на ошибку перевыпуска `leave` в Torch (для `patch_audit`).
- **`tools/`.** Скрипты извлечения гридов из сейва в ресурсы и проверки контрактов метрик.

## Сценарии

**Базовые**
- `smoke` — стенд жив: грид спавнится, двигается и удаляется.
- `patch_audit` — ни один перевыпускаемый Torch метод (патчи всех плагинов) не остался с изменённым
  потоком управления из-за ошибки `leave`.
- `patch_retbuf` — ни один перевыпускаемый Torch метод не получает аргументы не на своих местах: метод структуры
  (указатель на структуру копия принимает за объект) или экземплярный метод, возвращающий структуру через скрытый буфер.
- `patch_jumps` — каждый пропатченный Torch метод входит в копию прыжком из одной инструкции (SO `TorchJumpFix`): прыжок
  Torch из двух (`mov rax; jmp rax`) давал CLR неверно раскрутить стек при остановке потока на сборку мусора.
- `patch_params` — у каждого префикса и суффикса Torch и Harmony тип параметра тот же, что у передаваемого аргумента
  (число или структура, принятые за объект, — ссылка, по которой пойдёт сборщик).
- `wreck_restore` — восстановление провалившихся гридов SGI по одному на обломках мира «Wrecked Hauler» (двери,
  коннекторы): после исправления порядка выключения тел в `FallInVoxelDetector.MoveGroup` сервер не падает.
- `ground_probe` — реальный грунт (содержимое вокселей, а не сгенерированная поверхность) столбиками в точках
  колёсных площадок: где ямы, пещеры, насколько грунт ниже сгенерированного.
- `terrain_restore` — возвращает к сгенерированному грунт, накопанный сценариями, и колёсные площадки целиком
  (плитками по 100 м, кроме мест у статических гридов). Копающие сценарии (`voxel_stream`, `voxel_cache_resend`,
  `fall_through_tunnel`, `drill_perf`) теперь засыпают за собой сами (`WorldApi.RevertTerrain`).
- `bot_radiation` — бот SentisAi под радиацией пережидает её в своей герметичной кабине, а не умирает. Сценарий
  играет за планету (на Европе 0,6 в секунду всем, кто не в укрытии): начисляет радиацию боту стенда, пока тот
  на ногах. Бот должен сесть в кабину до 74,5, выйти, когда радиация спадёт, и не потерять здоровья. Нужен бот
  на ногах с ровером не дальше 300 м; идёт до 10 минут, в общий прогон не входит.
- `bot_pit` — бот SentisAi без водорода на дне шахты 26 м с камерой внизу (в 25 м от того места, где он стоял)
  должен выйти на поверхность за 6 минут в том же теле. `bot_pit_closed` — то же без шахты: над головой камень, устье
  его ямы в 2 м сбоку (задаётся боту), база в 350 м. `bot_pit_far` — то же без известного устья (как после перезапуска).
  Карманы бота заполняются камнем, чтобы он шёл домой. Грунт после себя возвращают. В общий прогон не входят.
- `bot_cliff` — бот SentisAi с полными карманами и без водорода в 45 м от базы, между ними воронка 20 м шириной и 13 м
  глубиной: должен дойти до базы за 4 минуты, ни разу не быстрее 12 м/с и без потери здоровья. `bot_cliff_h2` — то же
  с половиной бака: падение тормозит джетпак. Грунт возвращают. В общий прогон не входят.
- `bot_seat_finish` — пассажирское кресло на базе бота срезается до 60% (работает), компоненты кладутся в контейнер
  базы: бот должен доварить его полностью за 8 минут. В общий прогон не входит.
- `ai_status_ui` — страница SentisAi для Torch создаётся в своём потоке WPF и трижды спрашивает статус ботов: текст
  должен прийти, сервер — остаться жив (до исправления Torch падал в Havok, как только вкладку открывали).
- `bot_refuel` — бот SentisAi с пустым костюмом заправляется водородом у набора выживания своей базы от
  генератора O2/H2 (набор и генератор соединены конвейерами), без возрождения. Сценарий сам кладёт лёд в
  генератор, если его мало. Нужна такая база на стенде; до 12 минут, в общий прогон не входит.
- `turret_probe` — зонд, не тест: минуту пишет в лог состояние турелей на базах ботов и ставит волка в 30 м от
  заряженной турели: видит ли она его, берёт ли в цель, что стоит на линии огня.
- `fatal_exception` — роняет сервер нарочно необработанным исключением в отдельном потоке: проверка того, что
  `CrashDump` успевает записать полный дамп (`CrashDumps\crash_*.dmp`) до того, как Torch убьёт процесс. Только
  вручную, в общий прогон не входит.
- `struct_this_gc` — пропатченный метод структуры, лежащей полем объекта, переживает непрерывные сборки мусора
  (`MyExplosionInfo.AffectVoxels`: до 29.09.2026 сборщик падал на нём через секунды).

**Сварка и проекции**
- `projector_weld` — строительный корабль ванильными сварщиками строит проекцию 10×10 целиком.
- `mixed_weld` — то же с блоками всех типов; все функциональные блоки должны появиться.
- `frozen_radius_weld` — `projector_weld` после заморозки корабля, смены радиуса во время заморозки и
  разморозки.
- `hand_weld` — два персонажа ручной сваркой строят стену.
- `welder_perf` — шесть сварочных кораблей строят настоящий военный корабль из проекции, замер кадров.
  Чертёж корабля (Spitfire) встроен в плагин, грид в мире не нужен. Варианты:
  - `welder_perf_dynamic` — платформа динамическая, в открытом космосе;
  - `welder_perf_sz`, `welder_perf_sz_dynamic` — то же внутри безопасной зоны с выключенным уроном
    (платформа статичная / динамическая), с пробой зоны;
  - `welder_perf_sz_dynamic_noprobe` — без пробы, только кадры;
  - `welder_perf_sz_dynamic_vanilla` — то же с выключенным `SafeZoneGridTracking` (зона как в игре).

**Безопасные зоны**
- `safezone_border` — гриды поперёк границы зоны и внутри неё, к которым добавляют по блоку за кадр, и
  чужой корабль с ротором, 20 раз влетающий в зону и вылетающий из неё. Проверяет, что зона держит гриды
  после постройки, отпускает закрытые, ловит каждый вход и выход чужого корабля; меряет проверки форм,
  события фантома, блокировки моторов и стоимость отслеживания гридов.
- `safezone_border_vanilla` — то же с выключенным `SafeZoneGridTracking`.
- `safezone_ram`, `safezone_ram_vanilla` — корабль с пилотом на 100 м/с таранит статичную плиту в зоне с
  выключенным уроном (с трекингом плагина / как в игре). Проверяет, что ни плита, ни корабль не повреждены,
  что зона вносит корабль и выносит его после вылета и сообщает об этом клиентам; для контроля тот же
  таран вне зоны должен разбить оба грида.
- `projection_stream` — платформа с проектором доходит до клиентов.

**Производство и фризер**
- `production` — ванильная цепочка руда → завод → конвейер → сборщик.
- `refinery_perf` — 64 грида по 101 заводу, замер кадров переработки. `refinery_perf_busy` — то же, но каждый кадр
  искусственно нагружен на 13 мс перед обновлениями блоков (`Game/FrameLoad.cs`): проверка бюджета кадра SO
  (`ProductionFrameBudget`) — руда вся переработана, в игровых кадрах почти столько же, тиков заводов в разы меньше.
- `freeze_production`, `production_freezer_stress` — компенсация производства замороженных гридов:
  выход точно как у незамороженных.
- `freeze_power` — заряд батарей, уран и топливо у замороженных гридов.
- `freezer_physics`, `freezer_stress`, `freezer_stress_profile`, `piston_stack` — заморозка физики
  шасси, колёс, поршней и шарниров: ничего не отрывается, не проваливается и не улетает.
- `physics_resume` — кластер физики, где никого нет, и его возвращение, когда приходит игрок (SO
  `SelectivePhysicsBodies`). Риги с сабгридами на временной планете и в космосе, все в движении: скорость без шага
  не копится, после возвращения нет рывков, ничего не оторвалось. Фризер и очистка мусора на время прогона выключены.
- `unstepped_blocks` — там, где кластер не шагает, коннекторы не ищут пару и сенсор не смотрит (SO
  `SelectivePhysicsBodies`); пришёл игрок — через доли секунды кластер шагает, сенсор его видит, коннекторы сцепляются.
- `power_switch` — энергия грида следует за переключателями (SO `DistributorUpdate`): батарея, лампа, блок достроен и срезан.
- `panel_server` — у экрана программируемого блока на сервере применяется текст от модов и уходят клиентам
  нарисованные спрайты (SO `ServerGridRender` пропускает остальную отрисовку панелей).
- `fall_through_tunnel` — возврат провалившихся гридов (SGI `AutoRestoreFromVoxel`) не трогает то, что стоит
  под землёй нарочно. Плита в пещере под каменной полкой остаётся на месте, зарытая плита поднимается. Голова
  ротора статичного грида, зарытая в скалу, не двигается, и статичный грид тоже.
- `laser_link_awake`, `laser_control_anchors`, `remote_control_anchors` — замороженный корабль
  доступен через лазерную антенну и дистанционное управление.
- `pb_save_thread` — при сохранении мира `Save()` скрипта программируемого блока незамороженного грида вызывается
  в игровом потоке (SO `ParallelEntitySave`). На старой сборке он шёл на рабочем потоке, это причина падений старого
  сервера 28–29.09.2026.
- `pb_save_frozen` — у замороженного грида `Save()` скрипта, в котором есть код, при сохранении мира вызывается
  в игровом потоке, а гриды со скриптами с пустым `Save()` или без него собираются на рабочих потоках
  (SO `ScriptSaveCode`). Проверяет и то, как плагин читает скрипты, скомпилированные игрой.
- `frozen_save_perf`, `save_perf` — сохранение мира: снимок гридов и заранее собранные снимки
  замороженных.

**Производительность блоков**
- `drill_perf` — 32 корабля по 36 буров.
- `grinder_perf` — 400 резаков.
- `gas_perf` — 400 генераторов O2/H2.
- `thrust_ion`, `thrust_atmo` — двигатели под нагрузкой.
- `pb_perf` — тяжёлые программные блоки и их наказание.
- `piston_perf`, `piston_extend` — поршни в мире.
- `character_perf` — персонажи на джетпаках.
- `wheel_perf`, `wheel_perf_64`, `wheel_small*`, `wheel_parked_64`, `wheel_physics_ab` — колёсная техника.
- `wheel_fall*`, `wheel_restore*` — провал колёсной техники сквозь грунт и её возврат.
- `gear_probe` — в какую сторону защёлкивается шасси.
- `thrust_flame` — пламя двигателя жжёт броню только при тяге и на полную длину; десятикадровое обновление двигателя выключается.
- `turret_target` — турель без целей вокруг берёт в цель игрока, подошедшего на 60 м.
- `turret_wolves` — турель на батарее прямо на земле, вокруг четыре порождённых сценарием волка в 20–46 м с разных
  сторон: турель поворачивается от одного к другому и убивает всех, не стреляя мимо (ствол не дальше 25° от цели).
- `turret_wolf` — живой волк мира переносится в 30 м от самой высокой турели базы бота, турели даются магазины её
  типа; проходит, только если волка убила турель. `turret_wolf_idle` — то же с включённым вращением в простое.
  Сейчас падает: под турелью на 10-блочной мачте волк ниже 45° закрыт верхним блоком мачты.
- `turret_watch` — зонд, не тест: 15 минут смотрит на турели баз ботов как есть — в кого стреляют, что на линии огня,
  теряет ли цель здоровье; пустой турели со зверем в радиусе кладёт пять её магазинов.
- `pb_iim` — чертёж игрока с Isy's Inventory Manager (`C:\SE\tools\blueprints\iim_house\bp.sbc`, в репозитории его нет)
  вставляется статичным гридом с выключенным ПБ, ПБ включается как игроком; наказание SentisOptimisations включено. Три
  минуты пишет каждый замер PBFix (первые запуски, все дольше 2 мс с задачей скрипта), самый долгий кадр после вставки и
  после включения, и сгорел ли блок. В конце билдер грида собирается на рабочем потоке, ПБ должен остаться включённым.
  Наказание срабатывает только после 3 минут работы сервера. `pb_iim_watch` — то же без наказания.
- `pb_save_offthread` — ПБ со скриптом с `Save()` в гриде, вставленном из билдера: скрипт сам запускается, билдер грида
  дважды собирается на рабочем потоке (как параллельное сохранение замороженного грида), ПБ не выключается.

**Сеть**
- `replication_perf`, `replication_alloc` — 64 клиента, 64 завода и летающие корабли: репликация, мусор,
  время подключения.
- `voxel_stream` — подключение возле раскопанной планеты не останавливает сервер.
- `grid_stream` — подключение возле огромного грида.

**Игровые механики (SentisGameplayImprovements)**
- `explosions` — взрывы боеголовки и взрывчатки на плите брони, лут.
- `asteroid_field` — поле астероидов `!sgi spawnfield`/`spawnfield2`: место свободно, руды только заданные, общий цикл плагина не блокируется.
- `voxel_stuck` — застрявший в вокселях грид: в космосе переносится на 1 км в свободное место, сабгрид статичной базы и грид в гравитации становятся статикой.
- `explosion_friendly_fire` — взрыв не задевает свой грид при выключенном дружественном огне мира.
- `warhead_chain`, `warhead_mass_chain`, `warhead_mass_all` — цепные реакции и тысяча боеголовок разом.
- `cockpit_eject` — пилот уничтоженного кокпита выживает с 3% здоровья, пилот уцелевшего не задет.
- `loot_jumpdrive` — лут уничтоженного прыжкового двигателя считается один раз.
- `gravity_drive` — гравидвигатель не двигает корабль.
- `contract_prices` — множители наград контрактов: каждый игровой метод награды на работающем сервере при
  множителе 1 и 7.5.
- `pcu_limit` — лимит PCU: корабль сверх лимита (блоки выключены, на пятой проверке подряд статика),
  корабль в лимите, NPC-корабль, база с ротором (статичный лимит), сброс счёта после возврата в лимит.
  Проходы лимитера по миру на время сценария остановлены: он проверяет только свои гриды.
- `world_sweeps` — проходы плагинов по миру на гридах сценария: маяк контрабанды (учёт в радиусе, забывание
  ушедшего, цена прохода против старого при 2000 гридах), запоминание сканов фризера, выключение блоков без
  владельца и переименование, множитель резака по кадрам.
- `pcu_limit_cost` — цена лимита PCU для игрового потока: 20 копий Spitfire, проверка группы, перебор её
  блоков и проход по миру по вызовам; заодно проверяет, что счётчик PCU игры не меньше нашего ни у одного грида.
- `pve_zone` — PvE-зона: удары по блоку грида в зоне и вне её от чужого грида, персонажа, взрыва без
  владельца, своего грида, NPC (с `EnableDamageFromNPC` и без), контейнер `Container MK-`, грид, только что
  перенесённый в зону, выключенная зона; настоящие буры (чужой, свой, чужой вне зоны) и таран на 100 м/с;
  урон по персонажу в зоне от чужого грида, персонажа, корабля, взрыва без владельца, NPC, своего взрыва,
  удара о землю и вне зоны.

**Другие плагины**
- `garage_roundtrip` — VirtualGarage: грид в гараж и обратно целым, без пересоздания, без дублей.
- `watcher_record` — SentisWatcher: позиции игрока и грида, перенос предметов (запрос от клиента игрока), урон, содержимое инвентаря и «кто был рядом» записаны и читаются командами; честный перенос не даёт алерта о дюпе.
- `watcher_load` — SentisWatcher под нагрузкой: 64 Spitfire с игроками в кокпитах летают туда-сюда, двое прыгают; окна с записью и без сравнивают цену кадра, потом проверяется, что позиции, инвентари, захват управления и прыжки записаны и ничего не потеряно.
- `watcher_ledger` — учёт инвентарей SentisWatcher: честные перенос, сборка и переработка не дают алертов; сборка и разборка без входа, переработка без руды и правка стака в обход игры дают свои алерты; учёт игрока раскладывает каждое изменение по источнику (в том числе «плагин SentisTests» и «необъяснено»).
- `npc_spawn` — SentisAdventures:
  - NPC-корабль приходит целым и не пересоздаётся;
  - база на планете стоит вертикально, статично, низом на грунте, без блоков в скале.

## Запуск на стенде

1. Сервер с тестовым миром и всеми плагинами.
2. В чате или консоли Torch: `!test run <имя>`. Можно через DebugBridge: `POST /test`.
3. Результат в логе Torch (`Logs\Torch-<дата>.log`): `[TEST] PASSED`/`FAILED`, итоговая строка
   сценария и замеры.
